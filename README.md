# AgroOculus — схема обследования рисового поля

AgroOculus показывает, как система выбирает участок для повторной съёмки. Поле площадью 24 га разбито на 24 квадрата. Вид с виртуальной камеры обновляется прямо на схеме и следует за маркером во время полёта. На этапе «Сбор данных» кнопка «Получить кадр» сохраняет снимок из потока. На этапе «Обнаружение» кнопка «Обработать кадр» фиксирует изображение для распознавания, а «Вернуться к потоку» возобновляет просмотр.

## Открыть проект

[Запустить симулятор на GitHub Pages](https://zardol.github.io/AgroOculus/) · [Открыть блок-схему полёта](https://zardol.github.io/AgroOculus/flight-algorithm.html) · [Скачать схему для печати на А4](https://github.com/zardol/AgroOculus/raw/refs/heads/main/docs/flight-algorithm.pdf)

Для защиты откройте блок-схему. Проследите, как дрон проходит путевые точки, затем покажите, при каких условиях камера повторяет снимок выбранного сектора. Со стартового экрана симулятора запустите демонстрацию того же процесса.

Публичная версия работает в браузере без регистрации. Условия съёмки можно выбрать вручную, затем проверить решение и скачать показатели в CSV. Для сценариев и текстовых отчётов от Qwen откройте [версию с сервером Qwen](https://mezha-field-journal-kz04.tealblossom8.chatgpt.site) под учётной записью владельца или запустите проект на своём ноутбуке.

## Запуск на ноутбуке

В Windows распакуйте архив, запустите `start-qwen.cmd` из папки с `package.json` и откройте [рабочую станцию](http://127.0.0.1:8137). Оставьте окно сервера открытым на время показа. Требуется Node.js 20 или новее. Зависимости для запуска устанавливать не нужно.

Сервер берёт ключ из переменной среды `QWEN_API_KEY` или файла `апи.txt` на рабочем столе. Чтобы задать другой файл, запустите `node server/local.mjs "путь-к-файлу"`. Для проверки программы выполните `node --test`. Команда `npm run build` собирает версию для публикации.

Для показа без сети откройте `dist/index.html`. Карта, полёт, камера, распознавание, прогноз и ручное управление работают в браузере. Для генерации события и отчёта Qwen нужны сервер, интернет и действующий ключ.

## Как показать проект

1. На тёмной схеме нажмите **Запустить демо**. Экранный курсор выбирает элементы и ведёт через семь этапов. Переключатель скорости задаёт темп показа от 0,5× до 4×. **Автопрогон** проходит те же этапы быстрее, без указателя. Оба показа можно поставить на паузу и продолжить. Ползунок скорости полёта меняет скорость самого маркера в метрах в секунду.
2. Выберите **Ручной режим** и откройте нужный этап на схеме. На этапе **Маршрут** нажмите **Подобрать маршрут**. Программа сравнит круг, восьмёрку, галсы и путь по точкам. Сначала учитывается число посещённых секторов, при равенстве — длина пути. Галсы проходят через все 24 сектора. Собственный путь строится в обход насосной.
3. Откройте **Полёт** и нажмите **Запустить полёт**. Дождитесь завершения маршрута. На этапе **Обнаружение** выберите C5 и нажмите **Обработать кадр**. Детектор выделит на изображении пятно изменённой окраски. На этапе **Карта** осмотрите траекторию и собранные ориентиры, затем нажмите **Показать архив NDVI**. На этапе **Координаты** нажмите **Пересчитать**, чтобы получить метры от начала поля.
4. Для численного примера используйте сектор C5 и исходную ясную погоду в ручном режиме. Откройте **Решение**, оставьте порог 0,45 и нажмите **Проверить решение**. Вы увидите исходный снимок с NDVI около 0,262 и контрольный кадр. Сдвиньте порог до 0,20 и снова нажмите **Проверить решение**. Теперь система оставляет сектор в плановом обследовании.
5. Раскройте раздел **Формулы** на любом этапе. Подсказка поясняет смысл величин и подставляет значения из текущего опыта. На графиках можно показать, как менялись сигналы камеры и индекс, почему выбран маршрут и как менялась ошибка положения в полёте.
6. Нажмите **Сценарий от Qwen**. Модель может выбрать тень облака, подсыхание, потерю кадра или ясную погоду. На этапе **Решение** снова нажмите **Проверить решение**, затем **Составить отчёт**. Сервер повторяет расчёт по выбранным условиям и просит Qwen пояснить полученные значения. Отчёт сохраняется в TXT, показатели — в CSV.

## Семь этапов

| Экран | Что происходит |
| --- | --- |
| Сбор данных | Учебная камера формирует изображение и два канала отражения — красный Red и ближний инфракрасный NIR. После очистки архива остаётся 144 записи из 147. На отдельном примере показано, как медианный фильтр OpenCV убирает шум с кадра. |
| Маршрут | Система сравнивает охват и длину траекторий. Для обхода прямоугольной насосной она ищет кратчайший путь по графу видимости. |
| Полёт | PID-регуляторы корректируют скорость и курс маркера. Экран показывает его положение, пройденный путь и посещённые секторы. |
| Обнаружение | Детектор на базе YOLOv8 ищет пятна изменённой окраски на изображении посевов и распознаёт насосную на отдельном кадре. Результат — рамки, координаты в кадре и оценка уверенности. |
| Карта | Учебный метод SLAM совместно оценивает положение маркера и координаты наблюдаемых вех. Отдельный слой показывает архивный NDVI. |
| Координаты | Система переводит широту и долготу в метры от угла поля. Ошибку виртуального GPS и уточнённой позиции можно сравнить, поскольку истинная траектория известна. |
| Решение | Система сравнивает измеренный NDVI с порогом. При низком индексе учитывает изменение со временем, рамку детектора и уточнённый индекс. Пропуск кадра вызывает повторное получение снимка. |

## Что обучено

NDVI вычисляется по формуле `(NIR − Red) / (NIR + Red)`. Для базового кадра C5 отражение составляет 0,2493 в красном канале и 0,4261 в инфракрасном. Прогноз следующей даты и решение о текущем кадре выводятся раздельно.

- **YOLOv8** с одной шкалой детекции обучен на 320 синтетических изображениях, включая посевы и насосную станцию. На 96 контрольных кадрах 64 × 64 пикселя mAP@0,50 составила 0,995. При более строгой оценке совпадения рамок mAP@0,50:0,95 равна 0,867. На дополнительной проверке с полями вокруг кадра получено 0,866. Веса и расчёт детектора входят в проект.
- **CNN–LSTM** обучена на 3 072 синтетических спектральных последовательностях. На 384 отдельных примерах средняя абсолютная ошибка прогноза NDVI составила 0,0155. У переноса последнего значения ошибка равна 0,0248. Расширенный фильтр Калмана (EKF) уточняет оценку состояния по показаниям двух каналов и учитывает освещение.
- **Линейная и полиномиальная регрессии** прогнозируют NDVI. **SVM, дерево решений, случайный лес и XGBoost** классифицируют следующий срез относительно порога 0,45. В сводке методов последние 24 наблюдения оставлены для проверки. **Нечёткая система Мамдани** рассчитывает приоритет проверки по заданным правилам. Обучающие скрипты находятся в `tools`, параметры для браузера — в `dist`.

Поле, погода, камера, БПЛА, GPS и вехи смоделированы. Детектор обучался только на синтетических изображениях посевов и насосной станции. Качество на настоящих снимках и точность реального полёта в этой работе не измерялись. По одному пятну или низкому NDVI установить причину изменения растений нельзя.
